# Synso v1.1 修复轮 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉 v1 验收后实测暴露的启动卡死/设置慢/容量地图不刷新,交付根层磁盘使用率与「容量地图」改名,整体移除集合功能,并为内存优化完成测量拆账。

**Architecture:** 设置读走 Engine 内缓存(独立小锁)绕开被索引加载/扫描长期占据的 store Mutex;容量地图刷新 bug 以复现取证后修复;使用率叠加全部在 Rust 侧计算(`Engine::volume_overlay`,路径归一化与钳制可单测),前端只渲染;集合移除分引擎侧与 UI 侧两步删净;内存任务只测量、记录、定目标——优化本身是下一份计划。

**Tech Stack:** Rust(edition 2021, MSRV 1.83)· rusqlite(bundled)· sysinfo · Tauri v2 · Svelte 5 + TypeScript · ECharts sunburst。

**Spec:** `docs/superpowers/specs/2026-10-30-v1-fixes-design.md`

## Global Constraints

- TDD:每个行为改动先写失败测试(调试任务任务 2 例外:先复现取证)。
- 每步后 `cargo clippy -p <crate> -- -D warnings` 干净;性能/内存验收一律 release 构建。
- `synso-core` 不依赖 Tauri;UI 文案只在 zh/en 词典改,`npm run check:i18n` 必须过。
- 集合的 DB 表(`collections`、`collection_members`)保留在 schema,不迁移、代码不再触碰。
- 每任务一个或多个独立 commit,消息风格沿用仓库现状(`fix(core): …` 等)。
- 真实索引库位于 `%APPDATA%\com.synso.app\synso.db`(约 160 万文件);**任何探针只跑它的副本,不碰运行中的库**。
- i18n 无插值机制:复合文案由多个简单键在代码里拼接。

## Review Focus

1. **设置缓存写穿一致性**:`set_settings` 成功后 `settings()` 立即返回新值、重开 Engine 后仍是新值(写库与缓存更新丢失=缓存永久陈旧)。→ 任务 1 测试 `set_settings_roundtrip_cache_and_persist`。
2. **卷根匹配的路径形态**:Windows 上 `c:\` / `C:\` / `C:` / 尾随分隔符差异导致叠加时有时无。→ 任务 3 测试 `match_volume_normalizes_windows_paths`。
3. **未索引字段的下溢**:索引合计 > 物理已用时(稀疏文件/统计口径差)`unindexed` 必须钳为 0 且不显示负块。→ 任务 3 测试 `volume_overlay_clamps_unindexed`。
4. **移除集合后的 `coll:` 查询**:`coll:工作` 不再是修饰符,必须按字面文本回退且不 panic(与 `size:abc` 行为一致)。→ 任务 4 测试 `parse_coll_falls_back_to_literal`。
5. **事件风暴下的刷新坍缩**:连续删除/新建只触发一次去抖重取,不产生重取级联。→ 任务 2 手动清单第 3 条。
